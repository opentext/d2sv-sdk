Full width form for side-panel dialogs

Use the full_width_form attribute in the SDK dialog configuration XML to instruct the UI to render form elements at 100% width inside the dialog. This makes controls (text fields, selects, etc.) expand to the full available width when the dialog is displayed in the small side-panel size.

Important notes:

  • This only applies to small-size side-panel dialogs (side-panel size S). It does not apply to medium/large side-panel dialogs (sizes M, L) or to center-panel dialogs.
  • The attribute is added on the <dialog> element in the dialog XML and must be set to true to enable full-width rendering.

Example dialog XML with full_width_form enabled:

<dialog auto_smartview_edit_mode="false" buttons_right="false" focus="" height="500" id="SomeDialog" initial_invalid="false" resizable="true" signoff_creation="false" signoff_edit="false" signoff_import="false" signoff_intention_dictionary="" signoff_intention_required="false" width="400" form_mode="create" full_width_form="true">
  <content>
    <text advancedView_required="true" condition_required="true" control="true" id="name_field"/>
    <text control="true" id="description"/>
    <!-- other controls -->
  </content>
  <buttons>
    <button action="validDialog()" id="buttonOk" isPrimary="true"/>
    <button action="cancelDialog()" id="buttonCancel"/>
  </buttons>
  <signoff_fallback_message>
    <message locale="en" value=""/>
  </signoff_fallback_message>
</dialog>

Usage guidance:

  • Add full_width_form="true" to the top-level <dialog> element in the plugin's dialog XML (<Plugins Directory>/src/main/resources/xml/dialog/<Dialog Name>.xml).
  • Only small side-panel dialogs will render controls at 100% width; do not rely on this attribute to affect medium/large or center dialogs.

Troubleshooting:

  • If controls are not expanding as expected, confirm the dialog is opened in the small side-panel size and that no custom CSS or container markup is constraining control widths.
  • If you conditionally need full-width behavior at runtime, consider setting the attribute on the XmlNode returned by your dialog Java code (for chained dialogs or runtime decisions) before returning it.
